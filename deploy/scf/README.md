# 不用电脑、不用 Cookie：云函数 + PushPlus

这个目录是**匿名模式**的运行包：只抓服务端直出的 16 条「今日抢购」，不需要京东 Cookie、不需要浏览器，一次执行约 **0.3~0.5 秒**，推到微信（PushPlus）。

## 先说清楚能拿到什么

| 模式 | 商品数 | 需要 Cookie | 需要电脑 |
|---|---|---|---|
| **本方案（匿名 SSR）** | **16 条**（10 抢购中 + 6 预告） | 不需要 | 不需要 |
| 本机 CDP 方案 | 29 条 | 需要登录态 | 需要 Edge 常开 |

29 条里的另外 13 条（古井、茅台、膳魔师等 20:00 场）走的是登录态接口 `queryBabelFeeds`，匿名一律 403。**不用 Cookie 就拿不到这 13 条**，这不是实现问题，是接口鉴权问题。

16 条里已包含每天的主力日用品（稻香村、维达、可心柔、施华蔻、欧乐B 等），「抢购中 / 已售罄 / 剩多少」这些变化都在里面。

## 部署（腾讯云函数 SCF，免费额度足够）

### 1. 准备

- 一个腾讯云账号（实名）
- 已经注册 PushPlus 并拿到 token（你的是 `你的PUSHPLUS_TOKEN`）
- 微信关注「pushplus 推送加」公众号，否则收不到消息

### 2. 建函数

1. 打开 <https://console.cloud.tencent.com/scf>，地区选「上海」或「广州」
2. 左侧「函数服务」→「新建」→ 选 **从头开始**
3. 填写：
   - 函数名称：`jd-babel-push`
   - 运行环境：**Nodejs 18.15**（必须是 18+，内置 `fetch`）
   - 函数代码：选 **上传 ZIP 包** → 上传本目录的 `jd-babel-scf.zip`
   - 执行方法：`index.main_handler`
   - 内存：128 MB
   - 超时时间：**10 秒**
4. 展开「高级配置」→ 环境变量，加一条：

   | 变量名 | 值 |
   |---|---|
   | `PUSHPLUS_TOKEN` | `你的PUSHPLUS_TOKEN` |
   | `NOTIFY_MODE` | `new`（默认，只推新上架；`change` 连下架/价格变动一起推；`always` 每轮都推） |

5. 点「完成」

### 3. 加定时触发器

函数详情页 →「触发器管理」→「创建触发器」：

- 触发方式：**定时触发**
- 触发周期：**自定义**
- Cron 表达式：`0 */5 * * * * *`

> SCF 的 Cron 是 7 段：`秒 分 时 日 月 周 年`。`0 */5 * * * * *` 表示每 5 分钟的第 0 秒触发。

### 4. 试跑

函数详情页 →「函数管理」→「测试」→ 直接点「运行」。

返回里看到：

```json
{"ok":true,"products":16,"added":16,"removed":0,"changed":0,"first":true,"pushed":true,"sent":true,"elapsedMs":401}
```

同时微信会收到一条「加倍补 首轮基线 16 件」。

再点一次「运行」，返回 `"pushed":false`（无变化不打扰），说明增量判断生效了。

## PushPlus 相关

### 免费额度

免费用户每天 **200 条**。默认 `NOTIFY_MODE=new`，**只在有新商品上架时才推**，一天通常 0~3 条，基本用不完额度。

这几种变化**刻意不推送**（以免每 5 分钟一条）：

- 预约人数涨了/跌了
- 剩余件数、总量变化
- 商品售罄/恢复（除非你切到 `NOTIFY_MODE=change`）
- 价格微调（同上）

判定逻辑在 `src/snapshot.js` 的 `FIELDS`：只有 `price / listPrice / status` 参与「变动」，而 `new` 模式连变动都不推，只看新增商品。

### 消息样式

标题：`加倍补 +1 -0 ~0（16 件）`（有上新时）/ `加倍补 首轮基线 16 件`（首次）

有上新时：

```
加倍补 商品上新
- 时间：2026-11-06 3:25
- 当前商品数：16（上轮 16）
- 本次上新：1 件（💡 抢购中 0 · ⏰ 预告 1）

🆕 上新 · 1 件
- 100238264645 古井贡酒 年份原浆古20 浓香型白酒 52度 100ml*1瓶 单瓶装 积分兑换 ¥0.01（原价 ¥199） · ⏰ 预告（今天 20:00 开抢）2791/400
```

首次部署只确认通道，不刷屏：

```
加倍补 监控已启动
- 时间：2026-11-06 3:25
- 当前商品数：16（首轮基线）
- 规则：已建立基线，之后只在有新商品上架时推送
```

### 一对多推送

PushPlus 的群组功能：在公众号里建群组拿到 `topic`，再加环境变量 `PUSHPLUS_TOPIC=<topic>`，就能一次推给多个人。

## 关于基线（重要）

云函数的 `/tmp` 只在**同一个热实例**里保留。SCF 的定时触发器通常会让实例保持热 15~30 分钟，所以：

- 大部分轮次：能对比出增量，只推变化
- 冷启动后的第一轮：基线丢失，会推一次完整 16 条（标题是「首轮基线」）

这属于预期行为，不影响数据正确性。如果你希望严格只推增量，可以把基线存到对象存储（COS）或云数据库，需要额外加一个 SDK 依赖，本包为了「零依赖、上传即用」没有内置。

## 常见问题

**Q：返回 `解析到 0 条商品`？**
A：页面改版或被风控拦了。先在浏览器打开 `https://h5static.m.jd.com/mall/active/USFY4Q1KPsHd54cN8AVUPHZdHpT/index.html?babelChannel=ttt3&homepagebybt=1&secJump=1&visitScene=1`，搜索 `itemIdentityId`，看是否还是 16 个。若变成验证页，把触发间隔调大（10~15 分钟）。

**Q：微信没收到？**
A：① 关注「pushplus 推送加」公众号；② 在 PushPlus 官网「发送消息」页手动发一条，确认 token 有效；③ 看函数日志里 `sent` 是否为 `true`。

**Q：想改回 29 条？**
A：那必须用登录态。回到项目根目录，用 `--cdp` 连已登录的 Edge，或把 `JD_COOKIE` 填进 `deploy/.env` 用 Docker 版。

**Q：定时触发器没生效？**
A：SCF 定时触发器的时区是 UTC+8，`0 */5 * * * * *` 就是每 5 分钟，不需要换算。检查「触发器管理」里的状态是否为「已启用」。
